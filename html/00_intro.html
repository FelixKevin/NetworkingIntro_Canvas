0.1 Waarom een Backend? Terug naar boven

Vorig jaar hebben we ons vooral gefocust op de frontend van een website. We hebben geleerd hoe we een website kunnen opbouwen met HTML, CSS en JavaScript. We hebben geleerd hoe we een website kunnen stijlen, hoe we interactieve elementen kunnen toevoegen en hoe we de website kunnen laten reageren op gebruikersinput.

Met andere woorden, we hebben ons tot nutoe gefocussed op het deel van de website dat de gebruiker ziet en waarmee deze interactie heeft. We kunnen dit vergelijken met de UI van een applicatie. De frontend is echter niet in staat om gegevens op te slaan, te verwerken of te manipuleren. Zelfs toen we via een fetch-call gegevens naar een API stuurden, was het de API die de gegevens verwerkte en opslaat.

De backend is het deel van de website dat niet zichtbaar is voor de gebruiker. De backend is verantwoordelijk voor het verwerken van gegevens, het uitvoeren van berekeningen en het communiceren met de database, versturen van mails, genereren van PDFs, ...

De backend is dus een essentieel deel voor het bouwen van dynamische websites en webapplicaties. Zonder een backend zouden we geen gegevens langduren kunnen bewaren of andere complexere berekeningen maken.

0.2 LAMP via WSL Terug naar boven

Deze cursus zal je leren hoe je een backend kan bouwen met behulp van PHP en JavaScript. We zullen gebruik maken van de LAMP-stack, die bestaat uit:

  • Linux: het besturingssysteem
  • Apache: de webserver
  • MySQL: de database
  • PHP: de programmeertaal

Om deze stack te kunnen gebruiken, zullen we gebruik maken van WSL (Windows Subsystem for Linux). WSL is een compatibiliteitslaag voor het uitvoeren van Linux-binaries op Windows. Met WSL kunnen we een Linux-distributie installeren op Windows en kunnen we Linux-commando's uitvoeren in een terminalvenster. Eigenlijk is het een soort beperkte Virtual Machine, maar eentje dat reeds nauw geintegreerd is met Windows

Om WSL te installeren, volg je de instructies op deze pagina. By default zal WSL Ubuntu installeren als distro, maar indien je zelf meer ervaring hebt met andere distros kan je zonder problemen zelf eentje kiezen.

Na de installatie van WSL, kan je de LAMP-stack installeren door de volgende commando's uit te voeren in de terminal:

sudo apt update
sudo apt upgrade
sudo apt install apache2
sudo apt install mysql-server
sudo apt install php libapache2-mod-php php-mysql

Na de installatie van de LAMP-stack, kan je de webserver starten met sudo service apache2 start. Je kan de status van de servers controleren met sudo service apache2 status en sudo service mysql status.

De bestanden van de webserver worden standaard opgeslagen in /var/www/html. Je kan deze map openen in Windows door \\wsl$\Ubuntu\var\www\html in de adresbalk van Windows Explorer in te geven.

Om de PHP-bestanden te kunnen uitvoeren, moet je de bestanden opslaan in de map /var/www/html. Van zodra deze daar staan kan je deze openen in je browser door localhost in te geven in de adresbalk.

De MySQL Server is ondertussen reeds geinstalleerd, maar we gaan deze nog niet gebruiken. We zullen later in de cursus leren hoe we een database kunnen aanmaken en hoe we gegevens kunnen opslaan en ophalen.

0.3 Composer Terug naar boven

Composer is een dependency manager voor PHP. Met Composer kan je eenvoudig externe libraries en frameworks installeren en beheren. Composer is een command-line tool die je kan gebruiken om libraries te installeren, updaten en verwijderen.

We gaan Composer ook installeren op WSL. Om Composer te installeren, voer je de volgende commando's uit in de terminal:

sudo apt install php-cli unzip
php -r "copy('https://getcomposer.org/installer', 'composer-setup.php');"
php composer-setup.php
php -r "unlink('composer-setup.php');"
sudo mv composer.phar /usr/local/bin/composer

Na de installatie van Composer kan je Composer gebruiken door composer in te geven in de terminal. Je kan de versie van Composer controleren door composer --version in te geven.

Composer gebruikt een bestand composer.json om de dependencies van je project te beheren. In dit bestand geef je aan welke libraries je wil gebruiken en welke versie van deze libraries je wil gebruiken. Composer zal deze libraries downloaden en installeren in de map vendor.

De libraries die je installeert met Composer worden opgeslagen in de map vendor. Deze map gaan we niet tracken in git of uploaden naar onze GitHub, omdat je deze libraries opnieuw kan installeren met Composer.

Dit kan je doen door in een folder met een reeds bestaande composer.json file composer install in te geven. Composer zal dan alle libraries (opnieuw) installeren die in de composer.json file staan.

Om een nieuw project aan te maken met Composer, voer je de volgende commando's uit in de terminal:

composer init
composer require vendor/package

De eerste commando zal een nieuw project aanmaken en een composer.json bestand genereren. De tweede commando zal de library vendor/package installeren in de map vendor.

We gaan Composer gebruiken vanaf module 3, wanneer we starten met het bouwen van een backend met Laravel.
